# 物化视图

**一句话**：物化视图是真正存储查询结果的"可刷新的表"——建表时执行查询并存下结果（记住查询语句供刷新），读性能高但数据会陈旧，靠 `REFRESH MATERIALIZED VIEW` 手动更新，加 `CONCURRENTLY` 可刷新时不阻塞读。

## 骨架问题（带着问题学）

- 普通视图、物化视图、`CREATE TABLE AS` 三者差在哪？（物化视图 = 存数据 + 记住查询可刷新；CTAS 存数据但不记查询）
- 默认 `REFRESH` 为什么会阻塞读（排他锁）？`CONCURRENTLY` 如何做到刷新期间可查询，为什么前提是视图上必须有唯一索引？
- 刷新策略怎么选：定时 REFRESH / 触发器 / LISTEN-NOTIFY / CDC 增量刷新——陈旧度（staleness）容忍度如何决定方案？
- 和"自己写脚本把结果导成一张表"比，省了什么？（刷新逻辑数据库代管）代价是什么？（延迟、刷新成本、需要维护唯一索引）
- MySQL 8.0 为什么没有原生物化视图？常用什么替代（汇总表+定时任务）？
