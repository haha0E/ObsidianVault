# 异常链与Cause

**一句话**：catch 后重新抛出时必须把原始异常包进新异常的 cause，否则堆栈断裂，真正出错的那一行再也找不到。

## 骨架问题（带着问题学）

- `new RuntimeException("签名错误")` 和 `new RuntimeException("签名错误", e)` 打出来的日志差什么？排查问题时各是什么体验？
- 为什么"吞掉原始堆栈的自定义异常"是反模式？code review / 静态检查如何强制 catch 里 new 的异常必须带 cause？
- 自定义异常要不要故意"不提供不含 cause 的构造器"？这样做的利弊？
- `initCause()` 和构造器注入 cause 有什么区别？什么场景只能用前者？
- 错误信息分层：日志（给开发，要原始异常全量）与对外提示（给用户，要模糊安全）各自的原则是什么？
- 三方对接返回"10004 签名错误"这类粗粒度错误码时，如何在己方系统里保留足够的排查线索？
